# 从印谱学习字形风格，输入汉字生成

**当前起点是未整理的原始素材。** 用户没有提供已完成的字体训练划分或单字标签。此前出现的train/validation/test目录仅为程序生成的去噪实验副本；字体任务应先做[素材检查、字形与印风核对](DATA_READINESS.md)，再决定正式划分。下面的训练入口是数据准备完成后的工程工具，不表示原始图片现在即可训练出指定字形。

本模块的目标是：输入“印脉重生”，由训练后的模型生成同一印谱风格的四个字。与原先的图像去噪训练是两种不同任务。当前实现了单字框选、人工释文与风格标签、MySQL版本保存、训练样本导出、CUDA配对字形训练和实际模型生成。

**当前没有训练完成的印谱风格模型。** 13,646张现有图片是含多个印文的裁图，没有逐字释文。系统不会把文件名当作汉字标签，也不会用去噪权重冒充字形生成。界面中的“本机宋体风格流程验证”由本机Noto字体渲染的配对字形训练，仅验证生成链路，不代表已学会篆刻。

## 实际操作

可先使用[自动分割](AUTO_SEGMENTATION.md)减少手动框选。自动建议仅提供待核对边界，允许保存空释文草稿；填好并核对汉字后才可进入下面的字形训练流程。

1. 启动系统，进入 `/font`（“项目管理”或“增强与标注”右上角的“字形风格工坊”）。从原稿选择器选择印谱，或经 `/lab` 载入本机裁图，也可上传原稿。
2. 开启单字框选，逐字框出印文。每框只含一个字，避免印章外框；白文的框必须位于红色印面内部。填写一个对应汉字，选择朱文/白文/黑色字迹和是否需要镜像。框坐标相对原图保存，不改写原稿。
3. 给同一字形风格建立分组，如明确的印人/印风；一本印谱可能含多个风格，不能自动视作一种字体。填写标注人，对字形和释文有把握后勾选“已核对”。不确定的字不进入训练；备注记录异体与存疑处。点击保存。
4. 累积这一风格的多个不同汉字，点击“导出当前风格的训练字形”。样本包包含128像素单字掩膜和带原图SHA256、标注版本、字框、释文、朱白文及人工核对来源的清单。
5. 解压样本包，双击 `Start-Font-Training.cmd`，输入解压目录。入口默认使用当前GPU环境、NotoSansSC内容字体、30轮、batch16。高级参数：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/train-font.ps1 -Dataset 'D:/glyph-dataset' -Epochs 50 -Batch 16
```

没有NotoSansSC时，用 `-SourceFont` 指定可访问的汉字字体，并将后端的 `FONT_CONTENT_FONT` 配置为同一个文件。入口不自动下载字体或权重。训练使用PyTorch、Pillow、numpy、fontTools，需要CUDA；CPU不会被悄悄用作训练回退。

6. 训练结束后在 `/font` 刷新模型，选择风格、输入文字并生成。实际模型结果保存到MySQL资产和文件中，记录文字、模型哈希、内容字体哈希和训练来源。生成图片可下载；这一步尚不是制作TTF字体。

## 数据下限与评估

按**汉字**进行固定80/10/10划分，同一汉字的所有样本在同一组；不得把同一字的不同裁图随机分到训练和测试中。此任务与原去噪的“来源页划分”独立，原分组只作为来源信息保留。导出后若发现相同字形被标成不同字，则拒绝训练。

入口要求至少32个不同训练字、8个验证字、8个测试字。这个下限仅供流程基线，不能保证生成质量；实际应逐步积累覆盖常用偏旁、结构、笔画的数百至更多同风格字形。单张印章通常只有几个字，不足以可靠生成整个汉字集。

基线为386,849参数U-Net，输入标准内容字形，目标为人工标注的印谱单字；损失为前景加权BCE加边缘差异，按验证L1选模型，最后仅评估保留测试字。每个风格单独训练，**没有实现“随便给一张新参考图即生成”的少样本风格推理**。当前模型也不能保证把现代结构正确转成生僻篆体结构；目标掩膜保留原稿残损，不能当作完整的古字真值。

`models/font-generation/<运行ID>/` 保存TorchScript、模型卡、样本选用清单与保留字对照图；`evidence/font-runs/<运行ID>/console.log` 保存启动日志。字形图通过人工校字、轮廓矢量化和字宽/字距处理后，才能进一步制作可安装的TTF/OTF；本次未实现该步骤。

## 已实际完成的GPU链路验证

本机NotoSansSC → NotoSerifSC：1,027个不同汉字，816训练、97验证、114测试；RTX4060Ti训练30轮、1,530步，所有816个训练样本都实际参与。保留测试字前景IoU约0.559，直接照搬内容字体的IoU约0.404；这只是本机字体转换测试，不能作为篆刻风格效果指标。模型仅作为页面中明确标注的流程验证选项。

## 后续模型依据

已查看官方项目：[zi2zi](https://github.com/kaonashi-tyc/zi2zi)提供指定字形的配对风格转换路线；[MX-Font](https://github.com/clovaai/mxfont)提供多风格预训练后的少样本生成，并使用字形与部件信息；[FontDiffuser](https://github.com/yeungchenwa/FontDiffuser)提供内容/风格条件的扩散生成。它们说明可将内容与风格分别控制，不能据此宣称原始无标签印谱已能直接训练出准确字库。本次实现是独立配对基线，没有下载这些项目的第三方模型权重。
