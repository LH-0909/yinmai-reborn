# 2026-10-21 八页黑金视觉版

本轮已实际开发、运行并逐页截图。页面采用可操作的 Vue 组件，背景、印章、纹样与图标从用户提供的八张图片中提取。没有把整张截图铺成一个假界面。

视觉目标是八张 1672×941 参考图。**当前仍有字体、局部背景和组件细节差异，尚未通过像素完全一致的验收。** 原八页对照和问题见 `docs/design-qa-eight-pages-20261022.md`；根目录 `design-qa.md` 专门记录后续三维图谱的新视觉方向。原来的九页处理工作台继续保留，属于前一版视觉。

## 实际可操作的闭环

1. “视觉示例”模式呈现参考图中的示例数量、日期与画作。侧栏按钮可切换本机实值；它不是馆藏数量、AI成绩或订单的证明。示例图不自动进入真实作品统计。
2. 目录支持关键词、朝代、尺寸排序、本机收藏优先排序和材质筛选。每个收藏通过 PUT 写入 MySQL，刷新后保留。没有经过核验的流派标签会明确提示，不能凭图示自动编造流派分类。
3. 生成页保留创作提示区域。真正生成时另行确认 1—12 个汉字，使用规范字体进行排版，返回实际 PNG、SHA256、字体来源及非 AI 标记。此功能**没有学会篆刻风格**。
4. 朱文预览为红字；白文预览为红底白字。三维建模使用单独保留的规范笔画原图，避免把白文预览再次反转造成错误。每个预览和模型都有来源记录。
5. 三维印面调用原有重建接口，支持朱文／白文、镜像与毫米参数，返回真实封闭 STL。Three.js 读取同一个文件，支持旋转、缩放、线框与下载。狮钮雕塑仍为用户提供的概念画作。
6. 定制页的选择、滑杆、文字与材质会保存为参数草案，写入 MySQL。排版枚举保留在顶层，界面分类与细节放在 `customization` 下；参数变化不会假称生成了新模型。复杂刀痕、云龙纹、鎏金和印座尚未作用于实际网格。
7. 个人中心读取真实作品、收藏、参数方案与文件。规范字排版和参数草案有不同来源类型。实际导出只列出入库文件。支付、会员与公开发布未接入，实值模式不展示虚构订单。
8. 文化图谱与历史画作来自视觉参考。节点可检索项目已有知识条目；没有核实的年代、文物身份、地域分布与流派关系不作史实结论。设备语音使用浏览器语音合成，不冒充大模型讲解。

## 本轮接口与数据

新增 `backend/app/studio.py`。数据库在启动时创建 `studio_favorites`、`studio_settings`、`studio_designs`，均使用真实 MySQL。

| 接口 | 用途 |
|---|---|
| GET `/api/studio/catalog` | 明确标为未核实视觉参考的目录 |
| GET `/api/studio/state` | 真实收藏、方案、个人资料和统计 |
| PUT `/api/studio/favorites/{id}` | 幂等收藏或取消收藏 |
| PATCH `/api/studio/profile` | 本机个人资料 |
| POST `/api/studio/designs` | 保存参数草案，可关联来源作品 |
| POST `/api/studio/compose` | 实际规范字排版、入库和印泥预览 |

页面代码位于 `frontend/src/museum/`。原有 `App.vue` 保留为 `WorkspaceShell.vue`，由根组件按路由选择界面。旧上传、处理、训练、标注、三维和制造记录功能没有被移除。

## 验证

- 前端 TypeScript 检查和 Vite 生产构建通过，日志 `evidence/frontend-build-20261021.txt`。
- 65 项后端检查通过；测试采用独立 MySQL schema，不使用 SQLite 或假数据库。证据 `evidence/backend-tests.txt`、`backend-tests.xml`。
- 浏览器实际验证了收藏写入和重载、搜索、规范字生成、STL 预览与下载入口、定制滑杆参数保存。用户主库保留了验证时生成的“印脉重生”实际作品和参数草案。
- 八页在 1672×941 CSS 视口实际截图，图片加载失败和页面错误均为 0；389×844 窄屏检查中八页没有页面横向溢出。具体截图和 JSON 在 `evidence/ui-20261021/`。
- Windows 浏览器保留 79% 缩放，截图工具在右侧和底部附加空画布。原始 JPEG 完整保留；对照 PNG 仅裁去附加画布，不缩放、不修饰网页像素。
- 像素误差不是“还原率”。八页均未达到逐像素相等，数值与侧并排对照保存在 `pixel-comparison.json` 和 `*-compare.jpg`。
