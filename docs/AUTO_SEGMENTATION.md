# 自动分割与待整理字形

当前实现是OpenCV候选分割：提取红色或黑色印迹、定位主要印面、减少边框干扰、查找投影空隙，并对切断相连笔画的布局施加惩罚。程序建议行列与朱白文；它没有识别篆字，没有给图片自动填释文或风格，也不分配字体训练组。

## 网页操作

进入 `http://127.0.0.1:5173/font`，顶部选择一张原稿，点击“自动分割候选字形”。

- 自动模式建议布局；遇到粘连、边框、异形排印或分割不正确，可明确选择1至4行、1至4列，并切换朱文/白文/黑色字迹后重新建议。
- 空白草稿可直接接收候选框。已有字框会保留，本次结果需要点击“用本次候选替换当前字框”才替换；已保存版本不删除。
- 点击字框编号，在左/上/右/下百分比输入框调整边界。修改边界、朱白文、镜像或释文会清除该字的核对标记；也可删除候选、手动补框。
- 候选旁边显示原色字形缩略图。释文可以留空并保存草稿；未填写汉字不能勾选“已核对”，不会进入字体训练导出。
- 每次自动建议保存JSON版本、原稿SHA256、选项、候选框和算法来源，写入MySQL。人工草稿可绑定对应自动建议版本。

网页接口：`POST /api/seals/{id}/segment-glyphs`，需绑定当前原稿及SHA256。返回归一化框坐标；显示与裁图按EXIF方向一致。增强图或其他印谱的版本不能代替原稿。

## 批量入口

双击项目中的 `Segment-Images.cmd`。入口优先寻找项目随包素材或旁边的数据包，也可显式指定原图目录和输出目录：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/segment-images.ps1 -Source 'D:/my-seal-images' -Out 'D:/my-segmentation-results'
# 已知这批全部是四字方印时，可指定2行2列；该选项不是自动字数识别。
powershell -ExecutionPolicy Bypass -File scripts/segment-images.ps1 -Source 'D:/four-character-seals' -Layout '2x2' -Polarity 'bai'
```

分割使用CPU/OpenCV，不需要GPU。原始素材只读，结果必须写到另一个目录；已有结果不覆盖。

输出包含：

- `index.html` + `data.js`：可离线打开的浏览器，按文件名/建议布局筛选，显示原图候选框和对应裁图。
- `crops/`：原色候选裁图，保留观察到的残损与背景，没有生成或补写笔画。
- `previews/`：原稿上的候选框预览。
- `manifest.jsonl`：原图相对路径、原图哈希、候选坐标、朱白文建议、警示、候选裁图路径与哈希。
- `glyph-candidates.csv`：用于整理的清单；汉字、风格留空，人工核对为false，字体分组为unassigned。
- `summary.json`：实际处理数量和边界说明。

## 本机全库执行结果

2026-10-21，对本机保留的13,646张素材副本执行自动模式：13,646张完成处理，32,852个候选裁图；8,833张产生多个候选框，4,702张仅有一个候选（其中4,653张为1×1整印保留），111张未产生可用候选。111张中4张印面过小，107张的建议区域为空、占比不合适或不足8像素。输入文件未修改。结果目录为项目旁的 `yinmai-auto-segmentation-20261021/`。

**这些是候选数量，不是正确分割的汉字数量或准确率。** 1×1可能仍是一方含多个字的印章；其他布局也可能切到笔画、包含边框或估错字数、朱白文。没有专家单字框真值，本次没有测量真实分割准确率。

已经用合成已知布局检查朱文四字、白文四字、双字、指定行列、空白图和原稿溯源；另对48张真实样本生成预览并迭代。只有人工核对边界与释文后，候选才能成为字形训练样本。若要训练更可靠的字符检测模型，可把后续修正过的框作为标注来源，另建检测训练与独立评估集。
